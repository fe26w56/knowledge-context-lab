# 日本語調査資料の開発用fixture

このデータは、調査資料から根拠を取得する処理を試すために作成した架空資料です。独立した性能ベンチマークではありません。本文に登場する組織、場所、製品、数値、出来事を、実在する対象の事実として利用しないでください。

実ユーザーの資料、個人情報、実際のNotion URL、認証情報は含みません。`example.invalid` の出典URL、`bot_01` から `bot_16` の担当者、個別記録の識別語も架空です。ライセンスは未選定です。OSSとしての公開は、ライセンスと公開範囲を決めた後に行います。

## データの構成

| 項目 | 数 |
| --- | ---: |
| 文書 | 18 |
| 原文の節 | 61 |
| 質問 | 30 |
| 調整用の質問 `dev` | 10 |
| 評価用の質問 `eval` | 20 |
| 必須引用がある質問 | 26 |
| 情報不足の質問 | 2 |
| 権限外の参照を試す質問 | 2 |

`corpus.json` に本文と節を格納しています。節の本文は、文書本文に含まれる文字列と同じです。採用状態、有効期間、確認日、公開範囲は文書本文にも明記しています。構造化方式だけに正解となる事実を与えないためです。

`queries.json` の `request` だけを取得器へ渡します。`expected_quotes`、`forbidden_quotes`、`answerable`、`notes`、質問IDは採点用です。検索語、候補選定、要約、取得量の調整には使いません。

## 質問の範囲

通常の事実確認に加え、条件や例外、複数資料の組み合わせ、古い決定と後から書かれた提案、短い英字識別子、言い換え、引き継ぎ、参照範囲を扱います。文書量による改善を作為的に大きくしないよう、説明が短い文書も含めています。

`current` は現在有効な情報を求める要求です。提案の状態そのものを確認する質問には `search` を使います。`history` の質問では指定時点で有効だった旧版が必要です。この指定は全方式に同じように渡す実験条件であり、自然言語から正しく分類できたことを意味しません。

## 採点の解釈

`expected_quotes` は、回答に必要な原文が返却コンテクストに含まれるかを調べるための文字列です。すべて含まれていても、モデルが正しく答えることや、後続botが作業を完了できることは保証しません。断片を取り込んだだけで説明上の関係まで保たれるとも限りません。

`forbidden_quotes` は、権限外の個別記録が返却されないかを調べる識別語です。旧決定の文言を禁止引用にはしていません。履歴を説明するために旧決定を取得する場合があり、取得しただけでは誤回答と判断できないためです。

`answerable: false` の質問を、取得結果が空だったという理由で正答にしてはいけません。情報不足、検索失敗、参照権限の不足は別の状態です。これらの質問は必須引用の取得率から除き、情報不足への応答や権限制御を別に評価します。

## 評価用という表記の限界

`dev` と `eval` は、実装調整に使う問題と、調整後の比較に使う問題を区別するための名前です。同じ開発チームが資料と質問を作成しており、独立した第三者によるholdoutではありません。結果を見て方式を変更した後は、同じ `eval` を未見の評価とは扱いません。

実データでの採用判断には、別に選んだ実際の調査・引き継ぎと、必要な根拠を先に固定した評価が必要です。詳しい測定範囲は `docs/evaluation-protocol.md` を参照してください。
