# 確認済み原文の再利用：検証前の契約

2026-11-03。前回の最終問題は露出済み。親節重複の除去は保存済みpayloadの回帰試験とし、新しいモデル品質の主張には使わない。

## 仮説

1. 重なる原文範囲だけを統合すれば、情報を保ったままtokenが減る。
2. タスクが既知topicを指定する場合、質問を見る前に内容確認された原文範囲を返せば、資料の増加による検索・要約の揺れを抑えられる。
3. 原文・版・範囲に紐付いた引用IDをモデルに選ばせ、引用文字列をコードで返すと、引用の再生成エラーを防げる。ただし主張の意味的支持は別の評価。

比較は同じtopic_id/project/actor/modeを双方へ与える。これは業務上の参照キーで、問題IDや正解引用ではない。自由文からのtopic推定は対象外。原文のsource-firstレビュー範囲manifestを質問作成前に作り、架空の確認済み資料として扱う。本物の人手レビューや無料の知識構築とみなさない。

## 固定と比較

新fixture dev8/final12、各2質問表現。source/manifest/questions/mutations/generatorを実装前にhash固定。goldには問われる全決定・条件・例外・根拠を含める。private/unknownは不明を別評価、提案の内容確認と提案の採用を区別する。3件以上の実際の複数資料依存を監査する。

100/1,000/10,000 sources、同project内の他topicが増加。既知topicの全文を基準とし、同じsource集合の確認範囲を返す候補と比較。topic指定の効果と本文選択の効果と保存先の効果を混同しない。

候補は現在のsource集合の版/hashとレビュー時の集合を照合する。変更・新規追加・不可視化・廃止を検知したら古いcontextを返さずneeds_reviewまたはunavailableとする。全topic/sourceを一回のSQLite read transactionのsnapshotから解決し、同じsnapshotを明示的に使った16読者に同じ内容を配る。最新性と固定snapshot再現性は別契約。ローカルcallerが申告するactorを認証済み16agentとは呼ばない。

## 採用条件と費用

- 原文の全必要事実保持、private漏えい0、旧版・未レビューを現行確認済みにしない。
- 変更・追加・権限変更で旧contextを止め、再レビュー・復元・同時readで整合する。
- 返却JSON全体をo200k_base計数。構築/再レビュー/取得時間と16読者の実行を別記録。
- 実モデルは全文と確認済み原文で同じ質問に回答。同一入力の3反復を基本とし、事前計数した全対応roundが共有10 USD台帳の残りに収まる範囲で実行。
- 既存保守計上9.653204350 USD、不明予約2件維持。新試験は最大0.33 USD。料金や上限を都合よく下げず、呼出し失敗を自動再送しない。
- 第三の引用ID方式は同じ確認済み原文を使う。独立に比較できる予算がなければ、形式検査と保存済み引用の再構築のみ測り、実モデル効果を未測定とする。
- 必須事実正答、追加断定、厳密引用、token・usageを別集計。通常/未知/未レビュー/権限外を分ける。

最終開封後の失敗で検索を調整しない。結果が限定的でも適用可能な契約を明記する。自作診断であり独立benchmarkではない。公開・本番変更・新しい実資料の持ち込みはしない。
