# Completion verification protocol

Date: 2026-10-30. Active user goal: finish the experiments and implement a meaningful OSS system for 16 agents, preserving equal task quality with lower total cost/time. The previous 0.3.0rc1 is a preserved intermediate artifact, not completion of this goal.

Authorization: synthetic-only implementation and experiments; necessary network access; model experimentation capped at USD 10 total for this continuation (explicit user reply). The subsequent user steering requests use of existing ChatGPT credits. Prefer that credit balance; do not dispatch paid Cloudflare inference while the ChatGPT route is being resolved. No GitHub publication, production migration, secrets or real source documents imported. Do not charge unbounded retries or create a recurring paid service.

## Required evidence before completion

1. A new development/final fixture frozen before new retrieval implementation. Separate semantic review checks each question's complete claims, sources, states, times, conditions, abstention and private boundary. Question IDs, gold claims, expected quotes and generator lineage never enter retrieval or model inputs. Final data is held out until development selection freezes. Self-authored data is not an independent benchmark.
2. Ablations isolate changes: candidate ranking/coverage, eligible-section indexing, serialization, and storage. Compare A/B with the same candidate set, then B/C with the same exact payload. Compare 1,000/2,000/4,000 reference-token budgets; choose by development quality then measured payload/time. Test 100/1,000/10,000 documents, at least three independent generator seeds at the larger sizes. Report failure cases and corpus duplication rates, not only averages.
3. Actual model tasks must be run. Identical task/prompt/model/output contract across context variants, with recorded provider usage, outputs, latency, failures and retries. Measure answer claims and evidence citations separately. Task completion requires all specified claims/conditions, correct state and no forbidden leakage, or warranted abstention. Run 16 concurrently with separate actor identities and aggregate wall-clock and usage. Distinguish request-cost estimates derived from published rates, provider-reported usage, actual billed line items, free allocation and invoice evidence.
4. Integrate updates with retrieval: a committed revision must become searchable as a consistent snapshot, failed updates must not become visible, request retries must be idempotent, and backup/restore must report any acknowledged writes lost. Exercise 16 concurrent readers/writers and failure injection locally. If evidence favors a database/cloud design, verify that exact candidate on an isolated service before claiming adoption. A rejected D1 option need not be deployed merely to prove rejection, but a claimed D1 property requires a D1 measurement.
5. Runtime/package verification: supported Python versions, Linux when available, fresh wheel installation, source archive tests, exported fixture/run hash replay, license/provenance and a useful CLI/API. No unexecuted CI is a passing gate. If an unavailable service, rights decision or permission remains necessary, keep the goal active or report an actual blocker instead of declaring the narrower harness complete.

## Measurement and acceptance

Freeze the exact release candidate configuration and source hashes before final trials. Use per-question paired outcomes; seeds/repeats do not create independent questions. A candidate may be adopted only if declared task quality is no worse than the strongest tested comparable baseline, there are zero privacy/state violations, and the measured end-to-end resource tradeoff meets the task goal. If cost and latency trade off, show the frontier and select with an explicit rationale rather than claim both improved. Account for index build/update/retry cost and model response work. Human correction time cannot be fabricated; record observed task failures requiring correction and separately label any unmeasured human effort.

Before the first paid request, save a request bound and public pricing evidence. Reserve the upper bound before dispatch, including retries and concurrent work, and stop before the USD 10 cap. Save only synthetic requests and sanitized responses, never credentials/account personal data. Errors with uncertain billing consume their reservation until reconciled.

Prior final questions remain regression-only. Rejected fixture drafts and invalid diagnostics remain locally preserved and excluded from release claims. All new output directories use new runs/phase2-* names.
